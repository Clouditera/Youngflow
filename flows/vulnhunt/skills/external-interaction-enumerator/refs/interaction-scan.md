# 外部交互扫描方法论

## 任务目标

在指定范围内发现所有外部系统交互代码，输出完整的交互点清单。完整性是第一优先级——宁可多报，不可漏报。

## 方法论

### 搜索完整性

- **多角度交叉验证**：对同一类交互，用至少 3 种不同的搜索模式验证（库名、函数名、配置项）
- **不截断搜索结果**：禁止对搜索结果做 head/tail 截断。如果结果过多，按子目录分批搜索缩小范围
- **目录广度覆盖**：扫描所有源码目录。monorepo 中每个包都要检查
- **从已知交互出发**：验证 profiler 提供的交互点信息是否存在，Read 确认

### 扫描维度

根据项目实际使用的语言和框架，自行确定搜索关键词，覆盖以下维度：

| 类别 | 搜索方向 |
|------|---------|
| 网络请求 | HTTP 客户端库调用、gRPC stub、WebSocket connect、DNS 解析 API |
| 数据库操作 | SQL 查询构建（raw SQL/query builder）、ORM 调用、NoSQL 客户端、缓存读写 |
| 文件系统 | 文件读写 API、路径拼接、权限修改 |
| 命令执行 | Shell 调用、子进程创建、系统调用 |
| 消息传递 | 消息队列客户端、事件总线、IPC 通信 |
| 动态加载 | 动态库加载、动态模块导入、eval/exec |
| 目录服务 | LDAP 客户端、AD 查询 |
| 云服务/三方 API | AWS/GCP/Azure SDK、支付/邮件/短信 API |
| 代码执行框架 | Agent 工具注册、沙箱执行器、模板引擎调用 |

### 独立脚本目录

检查 `scripts/`、`bin/`、`cron/`、`jobs/`、`tasks/` 等目录下的独立脚本——它们不通过 Web 路由触发，但常将外部数据直接拼入 shell 命令或 SQL。

### 前端独立扫描

前端代码中的 WebSocket 连接、fetch/XHR 请求。特别关注连接目标 URL 来自用户可控输入 + 携带认证凭据的场景。

### 验证要求

- 搜索命中必须验证：确认是实际的外部交互调用，不是注释、测试或字符串常量
- 区分直接调用和封装层：既要记录封装层，也要搜索绕过封装的直接调用

## 输出格式

每个交互点一行，用 `|` 分隔：

```
交互类型 | 调用形式 | 文件 | 行号 | 备注
```
