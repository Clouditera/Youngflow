# 配置追踪任务

## 任务目标

对一组配置功能入口做深层代码追踪，生成一张标准化功能点卡片（FEAT-cd-*.yaml）。

## 输入

- 配置功能组名称和描述
- 配置入口列表（配置类型、配置项、文件、行号）
- 项目语言/框架
- 排除目录列表
- 输出目录路径

## 执行方法

### 核心方法论

#### 环境变量追踪

对每个环境变量引用，追踪四要素：

1. **变量名称**（`DATABASE_URL`, `JWT_SECRET` 等）
2. **使用场景**（数据库连接、密钥配置、第三方服务等）
3. **默认值风险**：弱默认值（`secret`, `password`, `admin`）→ 高危
4. **类型校验**：是否对值做类型/格式校验（防注入）

#### 动态加载检测（最高风险）

动态加载是最高安全风险的配置功能。对每个动态加载点，必须追踪：

1. 加载的类名/模块路径是否来自用户输入或外部配置
2. 是否有白名单限制可加载的类/模块（无白名单 → `risk_level: high`）
3. 加载后的代码在什么安全上下文中执行

额外关注：
- **框架安全旁路标志**：搜索 `allow_dangerous`、`sandbox=False`、`safe_mode=False`、`restricted=False` 等标志。这些与直接调用 `exec()` 等效但因封装在框架内部容易被忽略，发现即标记 `risk_level: high`
- **插件/扩展机制**：插件管理器、中间件链、过滤器链等可被外部扩展的执行点

#### 配置驱动文件路径检测

追踪链路：

1. **路径值来源**：硬编码 / 配置文件 / 数据库存储？数据库存储可通过管理界面修改，风险最高
2. **路径验证**：是否存在验证逻辑？常见弱验证：仅 `basename()`/`dirname()`、仅检查扩展名、`realpath()` 后不检查是否在预期目录内
3. **路径消费**：最终用于读取/写入/包含？结合消费方式判断风险（LFI/路径遍历/日志投毒→RCE）
4. **Web 可达性**：是否有 Web 接口允许通过该路径查看文件内容

#### 部署安全配置分析

先识别项目的部署方式（容器/K8s/裸金属/Serverless/移动端等），再针对该方式评估安全配置。核心问题：

- 服务是否以最小权限运行？（非 root、无特权模式、能力限制）
- 是否存在敏感信息泄露？（硬编码密码/密钥、镜像中的 .env）
- 是否存在不必要的暴露面？（host 网络、宿主机挂载、多余端口）
- 构建配置是否启用了安全编译选项？（C/C++ 项目：栈保护、PIE、RELRO）

#### 配置解析架构中的安全缺陷检测

某些框架使用集中的配置解析类来管理路由映射、视图映射或请求映射（如 `ConfigXMLReader`、`Router`、`RouteTable` 等类）。这些配置解析类定义的数据结构直接影响运行时认证/授权决策，但其本身可能存在安全缺陷。

**核心检测模式**：

1. **缺失安全字段**：配置解析类中定义的数据结构（如 ViewMap、RequestMap、RouteMap 等）缺少安全相关字段（`auth`、`permission`、`roles`、`securityLevel` 等），导致配置层无法强制要求认证
2. **危险默认值**：配置文件 schema 中安全属性的默认值为 `false` 或 `null`，且解析代码没有对缺失值做安全默认值填充（应默认为 `true`）
3. **解析结果未校验**：配置解析结果直接影响运行时行为，但解析代码本身没有验证安全属性的存在性或有效性
4. **配置与代码脱节**：配置解析定义了映射关系，但运行时 handler 没有读取和应用这些安全属性

**追踪步骤**：

1. **定位配置解析类**：搜索 `XMLReader`、`Config`、`Parser`、`Loader`、`Mapper` 等关键词，找到框架的集中配置解析类
2. **分析数据结构体**：在配置解析类中查找映射结构体定义（如 ViewMap、RequestMap 等），检查其字段列表
3. **检查安全字段缺失**：对比配置 schema（如 XSD、JSON Schema、配置文件 DTD），确认安全相关字段是否被定义
4. **追踪默认值**：检查配置解析代码中是否对安全属性做了默认值填充；如果没有，缺失安全属性的配置项将继承危险默认值
5. **验证运行时使用**：追踪映射结构体被消费的位置，确认运行时 handler 是否读取并应用了安全属性

**风险评估要点**：

| 条件 | 判定 |
|------|------|
| 配置映射结构体缺少安全字段，且运行时 handler 不做认证检查 | high |
| 安全属性（如 `auth`）默认值为 `false`，且解析代码未强制填充 | high |
| 配置 schema 定义了安全属性，但解析代码完全忽略该属性 | high |
| 配置映射结构体定义了安全字段，但运行时 handler 未读取 | medium-high |
| 框架默认行为是不认证（白名单模式），安全属性缺失时默认为不保护 | high |

### 追踪流程

从每个配置入口开始，追踪完整的数据流路径：

```
配置定义/读取 → 解析/校验 → 使用/影响运行时行为
```

#### 第一步：定位配置读取点

- 配置入口文件通常只包含配置声明或读取逻辑
- **必须追踪到配置值的实际使用处**，这是影响运行时行为的关键位置
- 如果配置值传递到另一个文件（跨文件引用），追踪过去并 Read 确认

#### 第二步：跨文件调用追踪

从配置读取点向下至少追踪 **2 层跨文件调用**，重点关注：

| 关注维度 | 原因 |
|---------|------|
| 配置值是否影响安全决策 | 认证绕过、权限提升 |
| 配置值是否拼接到命令/查询 | 命令注入、SQL 注入 |
| 配置值是否用于文件路径 | 路径遍历、LFI |
| 配置值是否用于动态加载 | 任意代码执行 |
| 配置值是否用于网络地址 | SSRF |
| 配置值是否有校验/过滤 | 校验绕过 |

#### 第三步：确定 code_locations

**核心原则：code_locations 覆盖完整数据流路径上的所有文件。**

- 每一层涉及的代码文件都必须进入 code_locations
- 行范围必须是**完整函数体**（函数签名到闭括号），不是 grep 命中行的前后几行
- 用 Read 工具实际读取文件确认函数边界

**大文件处理（>200 行）**：
1. 用 Grep 定位目标函数的行号
2. 用 Read 的 offset/limit 分段读取确认函数起止
3. **禁止只读前 100 行就下结论**——漏洞代码可能在文件后半段

**常见遗漏模式**（必须避免）：

| 遗漏 | 后果 |
|------|------|
| 只记录配置读取文件 | 安全分析器看不到配置值如何影响行为 |
| 只记录配置声明，不追踪使用处 | 遗漏配置值被拼接到危险操作的场景 |
| 只记录直接使用文件，不追踪校验层 | 遗漏校验缺失的问题 |
| grep 命中后不 Read 文件 | 无法确认函数边界和上下文 |

### 风险评估

| 等级 | 判定 |
|------|------|
| high | 动态加载无白名单；配置值拼接到命令/查询无过滤；弱默认密钥/密码；特权容器/root 运行；框架安全旁路标志 |
| medium | 环境变量有弱默认值但不直接暴露；配置驱动路径有部分校验；Feature Flag 可切换安全机制 |
| low | 硬编码配置项无外部可控性；部署配置符合安全基线；只读配置 |

### 自检清单

生成卡片前必须验证：
- [ ] **每个配置入口的使用处都在 code_locations 中**
- [ ] **processing_chain 引用的文件都在 code_locations 中**
- [ ] **code_locations 行范围是完整函数体**（用 Read 确认过，不是猜测）
- [ ] **动态加载点标注了是否有白名单限制**
- [ ] **弱默认值标注为高危**
- [ ] **大文件（>200 行）确认读取了目标函数所在行**（不是只读了文件头部）

## 输出格式

写入 `{output_dir}/features/FEAT-cd-{NNN}-{short_name}.yaml`：

```yaml
feature:
  id: "feat-cd-{NNN}"
  name: "{配置功能名称}"
  perspective: "config-deployment"
  risk_level: "{high/medium/low}"
  risk_rationale: "{具体原因}"
  description: "{功能描述}"
  language: "{语言}"

  entry_points:
    - type: "config"
      path: "{配置项/标识}"
      file: "{文件}"
      line: {行号}

  data_flow:
    input_format: "{输入格式描述}"
    processing_chain:
      - step: 1
        action: "{处理动作}"
        file: "{文件}"
        line: {行号}
        function: "{函数名}"
    output_format: "{输出格式}"
    secondary_parsing: false
    secondary_format: ""

  security:
    auth_required: {true/false}
    security_mechanisms:
      - name: "{机制名称}"
        coverage: "{full/partial/none}"
        location: "{文件:行号}"
        note: "{说明}"
    potential_risks:
      - risk_type: "{风险类型}"
        description: "{描述}"

  code_locations:
    - file: "{文件}"
      start_line: {起始行}
      end_line: {结束行}
      code_type: "{config_loading/dynamic_loading/deploy_config/business_logic/utility}"

  related_features: []
  discovered_by: "config-deployment-enumerator"
  confidence: "high"
```
